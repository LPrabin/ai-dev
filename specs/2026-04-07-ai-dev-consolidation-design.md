# Design: ai-dev Consolidation

**Date:** 2026-04-07  
**Status:** Approved  
**Complexity:** Medium

## Goal

Consolidate the split `~/.ai-dev` (source) and `~/.ai` (runtime) folders into a clean, git-driven architecture where:
- `~/.ai-dev` is the single source of truth (git repo)
- `~/.ai` is the deployed runtime
- Changes deploy automatically on commit, with manual fallback
- Mode-switching (`work`/`self`) is preserved

## Problem Statement

Current state has two folders that drift apart:
- Scripts differ between folders (4 missing in `.ai`)
- Unclear which to edit
- Mode-switching exists only in runtime, not source
- Manual sync is error-prone

## Components

### 1. `ai-deploy` Script

**Location:** `~/.ai-dev/bin/ai-deploy`

**Behavior:**
```bash
ai-deploy [--dry-run] [--force] [--quiet] [--install-hook]
```

**Flags:**
- `--dry-run`: Show what would be synced without doing it
- `--force`: Deploy even if working tree is dirty
- `--quiet`: Suppress output (for git hook)
- `--install-hook`: Configure git to use `.githooks/`

**Steps:**
1. Rsync `bin/`, `modes/`, `shared/`, `template/` to `~/.ai`
2. If no `~/.ai/context` symlink exists, create it pointing to `modes/work`
3. Run `build-context --adapter all`
4. Write deployment metadata to `~/.ai/.deployed`

**Rsync flags:**
- `-a`: Archive mode
- `--delete`: Remove files not in source
- `--exclude`: `.git`, `.DS_Store`, `prompts/`, `.deployed`, `.env`

**Protected paths (never touched):**
- `~/.ai/context` (symlink)
- `~/.ai/prompts/` (regenerated)
- `~/.ai/.env` (local secrets)

### 2. Git Hook

**Location:** `~/.ai-dev/.githooks/post-commit`

**Content:**
```bash
#!/usr/bin/env bash
ai-deploy --quiet || echo "Warning: ai-deploy failed" >&2
```

**Activation:**
```bash
git -C ~/.ai-dev config core.hooksPath .githooks
```

This is done by `ai-deploy --install-hook`.

### 3. Updated `ai-mode`

**Behavior:**
```bash
ai-mode work    # ~/.ai/context -> modes/work
ai-mode self    # ~/.ai/context -> modes/self
ai-mode         # show current mode
```

**Changes from current:**
- No longer runs `build-context` (deploy handles that)
- Just repoints the symlink
- Instant switching between deployed modes

### 4. Updated `build-context`

**Changes:**
- Reads mode-specific content from `~/.ai/context/` (the symlink)
- Reads shared content from `~/.ai/shared/`
- Assembles both into `~/.ai/prompts/global.md`
- Runs adapters to write tool-specific files

**Assembly order:**
1. `context/identity.md` (mode-specific)
2. `context/rules/*.md` (mode-specific)
3. `context/tools.md` (mode-specific)
4. `shared/skills/*.md`
5. `shared/agents/*.md`
6. `shared/mcp-servers.json` reference

## Migration Plan

### Phase 1: Backup
```bash
cp -r ~/.ai ~/.ai.bak.$(date +%s)
cp -r ~/.ai-dev ~/.ai-dev.bak.$(date +%s)
```

### Phase 2: Restructure Source

1. Create new directories:
   ```bash
   mkdir -p ~/.ai-dev/modes/{work,self}
   mkdir -p ~/.ai-dev/shared/{agents,skills}
   mkdir -p ~/.ai-dev/.githooks
   ```

2. Move context to modes/work:
   ```bash
   mv ~/.ai-dev/context/identity.md ~/.ai-dev/modes/work/
   mv ~/.ai-dev/context/rules ~/.ai-dev/modes/work/
   # tools.md if exists
   ```

3. Copy self mode from runtime:
   ```bash
   cp -r ~/.ai/modes/self/* ~/.ai-dev/modes/self/
   ```

4. Move shared content:
   ```bash
   mv ~/.ai-dev/context/agents ~/.ai-dev/shared/
   mv ~/.ai-dev/context/skills ~/.ai-dev/shared/
   mv ~/.ai-dev/context/mcp-servers.json ~/.ai-dev/shared/
   ```

5. Remove old context directory:
   ```bash
   rm -rf ~/.ai-dev/context
   ```

### Phase 3: Create New Scripts

1. Create `bin/ai-deploy`
2. Create `.githooks/post-commit`
3. Update `bin/build-context` to use new paths
4. Update `bin/ai-mode` to not call build-context

### Phase 4: Clean Deploy

1. Preserve `.env`:
   ```bash
   cp ~/.ai/.env /tmp/.ai-env-backup
   ```

2. Remove old runtime (except .env):
   ```bash
   rm -rf ~/.ai/bin ~/.ai/modes ~/.ai/shared ~/.ai/context ~/.ai/prompts
   ```

3. Run initial deploy:
   ```bash
   ~/.ai-dev/bin/ai-deploy
   ```

4. Restore .env:
   ```bash
   mv /tmp/.ai-env-backup ~/.ai/.env
   ```

### Phase 5: Install Hook
```bash
ai-deploy --install-hook
```

### Phase 6: Verify

1. Check mode switching:
   ```bash
   ai-mode work
   ai-mode self
   ai-mode
   ```

2. Check auto-deploy:
   ```bash
   echo "# test" >> ~/.ai-dev/README.md
   git -C ~/.ai-dev add -A && git -C ~/.ai-dev commit -m "test: verify auto-deploy"
   cat ~/.ai/.deployed
   ```

3. Check build-context output:
   ```bash
   cat ~/.ai/prompts/global.md | head -50
   ```

### Rollback

If anything fails:
```bash
rm -rf ~/.ai ~/.ai-dev
mv ~/.ai.bak.* ~/.ai
mv ~/.ai-dev.bak.* ~/.ai-dev
```

## Files to Create

| File | Description |
|------|-------------|
| `bin/ai-deploy` | Main deployment script |
| `.githooks/post-commit` | Auto-deploy hook |

## Files to Modify

| File | Changes |
|------|---------|
| `bin/build-context` | Read from `context/` + `shared/` |
| `bin/ai-mode` | Remove build-context call, just switch symlink |

## Files to Delete

| File | Reason |
|------|--------|
| `context/` (in .ai-dev) | Replaced by `modes/` + `shared/` |

## Out of Scope

- Changing the adapters (they still write to same tool-specific locations)
- Adding new modes beyond work/self
- Changing the Obsidian integration
- Modifying project-level scaffolding (`ai-init`)

## Risks

1. **Build-context breakage** — mitigated by testing before deleting backups
2. **Missing files in migration** — mitigated by explicit file list above
3. **Hook not firing** — mitigated by manual `ai-deploy` fallback

## Success Criteria

- [ ] Single edit location (`~/.ai-dev`)
- [ ] Auto-deploy on commit works
- [ ] Manual `ai-deploy` works
- [ ] Mode switching works
- [ ] `build-context` produces valid output
- [ ] All AI tools receive updated context
